## 1. What Ultra is

Ultra is an **Antelope (EOSIO) L1** operated as **Proof of Authority** — Ultra controls a
~7-BP producer schedule (EOSphere, EOS Sweden, EOSUSA, CryptoLions, …); there is no
token-holder BP voting. Runs Ultra's fork of **Spring** with **Savanna instant finality
live on mainnet**: 500 ms blocks, **~1 s deterministic BFT finality** (BLS quorum
certificates). No confirmation-depth heuristics needed; "irreversible" arrives in ~1 s.
Core token: **UOS, precision 8**, on `eosio.token`.

## 2. Accounts — Ultra's biggest divergence

**Account names are auto-generated by the system contract from an incrementing counter —
users do NOT choose names.** Four types
(`docs-blockchain/docs/blockchain/general/antelope-ultra/account-types.md`):

| Type | Name pattern | Keys | Use |
| --- | --- | --- | --- |
| **Ultra Account** (formerly EBA) | `aa1aa2aa3aa4` | key exportable; `owner` is null (backend-recoverable) | end users; **also deployable-from** (can't self-rotate `active` — see `08` §3) |
| **Ultra Pro Wallet** (formerly non-EBA) | `1aa2aa3aa4aa` | self-custody (`owner` + `active`) | developers — **recommended** for deploying (full key control) |
| Ultra Premium | e.g. `devname123` | self-custody | Ultra creates manually |
| Ultra Corporate | e.g. `partner.contract` | self-custody | Ultra creates manually (dotted names) |

- Creation actions on `eosio`: `newnonebact` (Pro Wallet — any existing account can be
  `creator` and pays `max_payment`, priced in USD via the oracle; ~2 USD in UOS) and
  `newebact` (Ultra Account — `require_auth(major_idp)`, i.e. **only Ultra's backend** can
  create EBAs). Ultra sponsors the initial account RAM (~5 KB free).
- Dotted names (`ultra.dex`) exist only via privileged creators (`eosio`/`ultra.eosio` —
  Ultra's `newaccount` has **no suffix rule** for them). On a local test chain you can do
  the same (see `04`); on mainnet, dotted contract accounts are an Ultra-granted thing.
- Antelope `name` type: ≤12 chars, base32 (`a–z`, `1–5`, `.`) — applies to **account,
  action, and table names** (that's why real actions are named `removeliquid`,
  `withdrawcoll`).

### 2.1 Keys & permissions

- Key types: K1 (secp256k1, the default `EOS…`/`5…` pairs), R1, WebAuthn.
- Every account has `owner` and `active`; **Ultra divergence: `active` may NOT change its
  own keys** (vanilla EOSIO allows it). EBA key rotation flows through
  `eosio.eba::updateactauth` (Ultra backend).
- Authorities are **recursive threshold trees**: `{threshold, keys:[{key,weight}],
  accounts:[{permission:{actor,permission},weight}], waits:[…]}`, depth ≤ 10. Custom
  permissions + `linkauth` bind a permission to one `contract::action`.
- Deep reference incl. `get_accounts_by_authorizers` semantics:
  `[internal: ultraOS-doc web-browser-extension/EOSIO_ACCOUNT_AUTHORIZATION.md]`
  (public equivalent: developers.ultra.io → accounts-and-permissions).
- A contract that sends inline actions needs `eosio.code` on its `active` permission
  (`cleos set account permission <acct> active --add-code`).

## 3. Resources — POWER + Ultra's RAM policy (no gas)

**There are no per-transaction fees.** Ultra reworks vanilla CPU/NET:

- **POWER** = CPU+NET combined, staked via `delegatebw`/`undelegatebw`. **Zero-POWER
  accounts can still transact** — free transactions are included after staked ones, and a
  two-queue scheduler (80/20 positive/negative split, 50 ms rate-limit threshold) rate-limits
  abusers rather than charging anyone. Practical effect: users don't pay to use your dapp.
- **Predicate system** (Ultra-only): a developer can sponsor third-party users' resource
  costs from the developer's own POWER (`allowpred`/`revokepred`), optionally gated by an
  on-chain predicate action. No PowerUp/REX rental documented on Ultra prod.
- **RAM** is the real cost and the real gate. Ultra-specific policy
  (`ram-policy.md`, `ram-market.md`):
  - bought in UOS (`buyram`/`buyrambytes`), Bancor-priced in USD terms; refundable via
    `refundram` (purchase fee — docs state 5% in one place and 10% in another; verify
    live — is not refunded);
  - **new accounts start with Ultra's sponsored ~5 KB RAM**; buy more with
    `buyram`/`buyrambytes` as needed — **no KYC gate; deployment is permissionless** (`08` §4);
  - **developers pay RAM for their users** (contract pays for user rows — see the notify
    RAM rule in `03`), and only registered developers can buy in bulk;
  - Ultra can gift RAM (`giftram`) and runs sponsored tiers (free storage for keys/
    permissions on user accounts).

## 4. UOS and fungible tokens

- **All fungible tokens live on the single `eosio.token` contract** — a token is
  identified by `extended_symbol {sym:"8,UOS", contract:"eosio.token"}`, not by a contract
  address. UOS: precision 8, issuer `eosio`, ~1.0176 B supply, no tax/burn configured.
- Ultra's `eosio.token` extensions: anyone can create non-premium tokens (issuer pays
  RAM); premium symbols reserved; per-symbol **tax** (`configtax`) and **burn**
  (`configburn`) configs exist → **contracts handling arbitrary tokens must check the
  `tokenconfig` table and reject taxed tokens** (the DEX's `is_taxed` pattern, `03` §6).
- `transfer(from, to, quantity, memo)` — recipient balance rows auto-open (`eosio.token`
  pays that RAM). The `memo` string is the universal dapp routing channel (`03` §4).
- `ultra.swap` is the legacy pNetwork bridge (PUOS/PUSDT); `ultra.bridge` is the
  Ultra↔EVM/Ethereum bridge. Both names are taken — relevant when picking contract names.

## 5. Uniqs — Ultra's NFT standard (`eosio.nft.ft`)

> Integrating (not just understanding) Uniqs or any other system contract? → **`11`** — the
> source is private but every ABI is public; `11` shows how to pull it and the verified
> action/table shapes.

Factory → token model on contract account `eosio.nft.ft`:

- **Factory** (`factory.b` table): collection definition — metadata URI+hash, mint limits,
  trading/transfer windows, immutable `resale_shares` (≤70% total), first-hand purchase
  requirements. **Factory creation is currently Ultra-gated** (`tfcreateflag.require_ultra`
  = true — you apply to Ultra / use the Factory Manager product; plan for this).
- **Token** (`token.b`, scope = owner): the Uniq — global ID + per-factory serial.
- Lifecycle actions: `issue.b` (mint, incl. authorized-minter quotas via `authmint.b`),
  `transfer`, `resell`/`buy`/`cancelresell` (second-hand market with **Ultra global share
  2%**, factory shares ≤70%, promoter 2–10% — an unset promoter pays the default promoter
  `ultra.dfprom`, not zero), `burn`, auctions (`createauct.a`…), offers (`mknftofr.a`…),
  first-hand `purchase.a` with UOS- or USD-priced options.
- Factory RAM is covered by `eosio.nftram`; non-Ultra asset managers pay a USD-priced UOS
  fee via the oracle.
- Read Uniq data: on-chain tables, or the public GraphQL APIs (`07` §1.3).

## 6. The oracle (`eosio.oracle`)

Ultra-run price oracle: registered exchanges push UOS/USD; the contract computes
volume-weighted, outlier-rejected SMA/EMA moving averages. **Rate symbol `DUOS` (8,DUOS) =
USD per 1 UOS.** Anyone can read:

- `lastknwnrate` (scope `eosio.oracle`) — latest rate.
- `finalaverage` (scope = `SECONDS`/`MINUTES`/`HOURS`/`DAYS`; primary key
  `window*10000 + α*10000` — the 1.0000-MINUTES SMA is key `10000`) — the moving averages.
- In-contract reads mirror `moving_average_impl`'s field order — worked read-path example
  `[internal]`; the local-test gotcha is in `04` §7.

The oracle prices system things too (account creation, NFT fees, BP pay) — it is always
initialized on real networks, but a **local test chain pushes no rate by default** (`04`).

## 7. System contracts & governance map

Privileged/system accounts: `eosio` (system contract: RAM market, POWER, account
creation, KYC policy), `eosio.token`, `eosio.msig`, `eosio.wrap`, `eosio.nft.ft`,
`eosio.oracle`, `eosio.eba` (EBA flows), `eosio.kyc` (on-chain KYC certificates),
`eosio.group` (user groups), plus app contracts `ultra.bridge`, `ultra.swap`,
`ultra.cntmgr` (**chain-wide kill-switch that can disable a specific `contract::action`**),
`ultra.fctmgr`, `ultra.rng` (BP-run RNG oracle), `ultra.claim`, `ultra.rgrab`,
`ultra.avatar`, `ultra.discord`, `ultra.tools`.

Governance: `eosio` is owned by **`eosio.prods`** (the BP msig) — and **Ultra's approval is
required on every msig proposal**. `eosio.wrap` + 2/3 BPs can freeze any account. For your
contract this matters twice: (1) system-level changes go through the producer msig; (2) the
shipped-contract convention is to hand admin to `eosio` post-launch (`08` §5).

## 8. Execution model facts that shape contract design

(Full treatment with code patterns → `03`; verified against Spring source.)

- **No synchronous inter-contract calls** (CDT 3–4.x). Composition = inline actions +
  notifications + closing assertions, all inside one atomic transaction.
- **Inline actions execute depth-first**; `require_recipient` notifications run before the
  next sibling action. This ordering is load-bearing (it's why flash loans work).
- **No deferred transactions, no native cron** — scheduled behavior needs off-chain bots.
- **Read-only actions** exist (`[[eosio::action, eosio::read_only]]`).
- Whole-transaction atomicity: any assert anywhere reverts everything.

## 9. The differences cheat-sheet (Ultra vs vanilla EOSIO)

1. Names auto-generated; account types EBA vs Pro Wallet; dotted names are privileged.
2. `active` can't rotate its own keys; EBA rotation via `eosio.eba`.
3. Account creation gated (EBA = Ultra IdP only); Ultra sponsors creation RAM.
4. **Mainnet contract deployment is permissionless** — no Ultra authorization, no KYC; any
   account (EBA key now exportable, or a Pro Wallet) + UOS + RAM — details `08` §4.
5. RAM: dev-pays-for-users, buy/refund via `buyrambytes`/`refundram`, Ultra reserve/gifting.
6. Resources: POWER (CPU+NET merged) + free rate-limited txs + predicate sponsorship;
   no gas, no PowerUp.
7. One `eosio.token` for all fungibles; per-symbol tax/burn configs; premium symbols
   reserved.
8. NFTs = Uniqs on `eosio.nft.ft`; factory creation Ultra-gated; protocol/promoter share
   model.
9. PoA governance: `eosio.prods` msig with Ultra veto; `ultra.cntmgr` kill-switch;
   `eosio.wrap` freezes.
10. Savanna ~1 s finality live — design for it (e.g. backends can act on IRREVERSIBLE
    events with ~1 s lag).
11. `ultra.*` / `eosio.*` namespaces are reserved; several good names are already taken.
12. Ultra EVM runs in parallel (own chain ID/explorer/bridge).
